# 🍜 Oppa Ramyeon POS — v1.3.0

ระบบ POS ครบวงจรสำหรับร้านมาม่าเกาหลี: หน้าขาย, เลขคิว, ใบครัว/จอครัว, เครื่องพิมพ์จริง (USB/LAN/Bluetooth/Serial), เสียงแจ้งเตือน, จอลูกค้า (ลิงก์+รหัส และ Dual Screen), รอบการขาย, สต็อก/สูตรวัตถุดิบ, กฎนับชาม, รายงานและวันขาย, Mobile Ordering, พร้อมเพย์/Beam Checkout, สมาชิก/แต้ม/Tier/รางวัล, เว็บไซต์สมาชิก, ตัวออกแบบเอกสาร, ศูนย์ฟอนต์ และเว็บไซต์จัดการร้าน — ทุกหน้าใช้ฐานข้อมูลเดียวกันและอัปเดตแบบเรียลไทม์

คู่มือการใช้งานทุกฟังก์ชันอยู่ในระบบที่ **`/guide/`** (มีปุ่ม 📖 คู่มือ บนหน้า POS)

| หน้า | URL | ใช้ทำอะไร |
|---|---|---|
| หน้าขาย POS | `/pos/` | ขาย สแกน รับชำระ ส่งครัว รอบการขาย อุปกรณ์ |
| เว็บไซต์จัดการร้าน | `/admin/` | ยอดขายวันนี้ รายงาน บิล เมนู สต็อก สมาชิก ตั้งค่า |
| จอครัว | `/kitchen/` | ใบครัวเรียลไทม์ พิมพ์ใบครัว เสียง |
| จอลูกค้า | `/display/` | จับคู่ด้วยรหัส 6 หลัก / จอที่สอง |
| Mobile Ordering | `/m/#<token>` | ลูกค้าสั่งผ่าน QR ที่พนักงานพิมพ์ให้ |
| เว็บไซต์สมาชิก | `/member/` | บัตรสมาชิก แต้ม คูปอง รับแต้มจากใบเสร็จ |
| คู่มือ | `/guide/` | วิธีใช้ทุกฟังก์ชัน การเชื่อมต่ออุปกรณ์ |

## เทคโนโลยี
- Node.js 22 + Express + Socket.io (ไม่มีขั้นตอน build ฝั่งหน้าเว็บ)
- PostgreSQL (เมื่อมี `DATABASE_URL`) หรือ SQLite ในตัว (`node:sqlite`) สำหรับรันในเครื่อง — SQL ชุดเดียวกัน
- เงินเก็บเป็นสตางค์ (จำนวนเต็ม), เก็บทั้งเวลาจริงและ "วันขาย"
- เอกสารพิมพ์เรนเดอร์เป็นภาพ ESC/POS raster จากแม่แบบ JSON — ตัวอย่างบนจอและผลพิมพ์ใช้ตัวเรนเดอร์เดียวกัน

## รันในเครื่อง
```bash
npm install
npm start            # http://localhost:3000  (SQLite ที่ ./data/pos.db)
npm test             # ชุดทดสอบตรวจรับ 55 รายการ
TEST_DATABASE_URL=postgres://user@host/db npm test   # ทดสอบบน PostgreSQL
```
เข้าระบบครั้งแรก: รหัส `0001` PIN `1234` (หรือค่า `OWNER_PIN`) · แคชเชียร์ `0002`/`2222` · ครัว `0003`/`3333` — **เปลี่ยน PIN ทันที**

## Deploy บน Render
ไฟล์ `render.yaml` สร้าง Web Service ชื่อ `opparamyeon` (URL `https://opparamyeon.onrender.com`) และ PostgreSQL `opparamyeon-db`

| Environment | ความหมาย |
|---|---|
| `DATABASE_URL` | ต่อจากฐานข้อมูลอัตโนมัติ |
| `PUBLIC_URL` | URL เว็บไซต์ (ใช้สร้าง QR ใบเสร็จ/Mobile Ordering) |
| `OWNER_PIN` | PIN เจ้าของร้านตอนสร้างฐานข้อมูลครั้งแรก |
| `SEED_DEMO` | `true` = ใส่เมนูตัวอย่างเมื่อฐานข้อมูลว่าง |
| `BEAM_MERCHANT_ID` / `BEAM_API_KEY` / `BEAM_WEBHOOK_SECRET` | (ไม่บังคับ) Beam Checkout — ปกติกรอกเองที่ จัดการร้าน → การรับชำระเงิน (เก็บในตาราง secrets ฝั่งเซิร์ฟเวอร์) |
| `OTP_WEBHOOK_URL` / `OTP_WEBHOOK_TOKEN` | (ไม่บังคับ) ช่องทางส่ง OTP ผ่าน SMS |
| `MOCK_WEBHOOK_SECRET` | (ทดสอบ) ลายเซ็นของ Mock Gateway |
| `UPLOAD_DIR` | (ไม่บังคับ) เก็บไฟล์บน Disk แทนฐานข้อมูล |

ข้อควรรู้: แผน Free ของ Render — Web Service หลับเมื่อไม่มีการใช้งาน ~15 นาที (เปิดครั้งแรก ~1 นาที, จอลูกค้า/POS จะเชื่อมต่อใหม่เอง) และ Free Postgres หมดอายุใน 30 วัน — ร้านที่ใช้งานจริงควรอัปเกรดเป็นแผนเสียเงิน · ไฟล์อัปโหลด (รูป วิดีโอ ฟอนต์) เก็บในฐานข้อมูลเพื่อไม่หายเมื่อ deploy ใหม่

## การเชื่อมต่อฮาร์ดแวร์
- **USB**: WebUSB บน Chrome/Edge (Windows อาจต้องเปลี่ยนไดรเวอร์เป็น WinUSB ด้วย Zadig) และ Chrome Android ผ่าน OTG
- **LAN / USB บน PC**: รัน Print Agent บนคอมพิวเตอร์ในร้าน
  ```bash
  node agent/print-agent.js --origin https://opparamyeon.onrender.com
  # http://127.0.0.1:9123/status · /scan (หาเครื่องพิมพ์พอร์ต 9100 ในวง LAN) · /usb
  ```
- **Bluetooth**: BLE ผ่าน Web Bluetooth · Bluetooth Classic (SPP) ใช้ Serial/COM หรือแอป Android ที่มี OppaBridge
- **สถานะงานพิมพ์ตามจริง**: `sent` = ส่งถึงเครื่องแล้วแต่เครื่องไม่รายงานผล · `printed` = เครื่องตอบสถานะปกติ (DLE EOT) · ผิดพลาด/ไม่ทราบผล → ลองใหม่ด้วยมือ (ไม่พิมพ์ซ้ำเอง)

### สัญญา Android native bridge (สำหรับแอปห่อ WebView บนเครื่อง Dual Screen / POS มีเครื่องพิมพ์ในตัว)
แอปฉีด object `window.OppaBridge` ที่มีเมธอด:
- `openCustomerDisplay(url: string)` — เปิด `url` บนจอที่สอง (Android `Presentation`/`DisplayManager` หรือ SDK ผู้ผลิต เช่น Sunmi/iMin) และจำจอที่เลือก
- `print(json: string): Promise<string>` — `json = {conn, address, port, data(base64 ESC/POS)}` คืนค่า `{"ok":true,"status":{"known":true,"paperOut":false,"coverOpen":false,"error":false}}`
ถ้าไม่มี bridge ระบบใช้การเปิดลิงก์ `/display/` + รหัสจับคู่แทน

## ผลการทดสอบ (อัตโนมัติ)
`npm test` ผ่าน 55/55 ทั้งบน SQLite และ PostgreSQL 16 ครอบคลุม: สแกนซ้ำเพิ่มจำนวน, เลขคิว/เลขบิลไม่ชนเมื่อขายพร้อมกันหลายเครื่อง, ทานที่ร้าน/กลับบ้านตรงกันทุกเอกสาร, ใบครัวแยกชามและท็อปปิ้ง, ส่งเฉพาะรายการเพิ่ม/ใบยกเลิก, เครื่องพิมพ์เดียวหลายงานเรียงลำดับ, สถานะพิมพ์ตามที่อุปกรณ์ยืนยัน, จอลูกค้าจับคู่/ยกเลิก/แยกเครื่อง, ช่องกรอกสมาชิกผูกบิล, ยอด/บิล/ชามตรงกันระหว่าง dashboard รายงาน และรอบการขาย, Refresh ถี่ไม่ทำให้ยอดผิด, ยกเลิก/คืนเงิน/ตัดวันขาย, ใบ QR ออกเมื่อเลือกเท่านั้น, QR หมดอายุ/ปิดรอบ/ใช้ครั้งเดียว, โต๊ะ/Pick Up, แจ้งเตือนชำระที่แคชเชียร์, สลิปไม่เปลี่ยนสถานะเอง, webhook ปลอม/ซ้ำ/ล่าช้า, จ่ายหลังหมดอายุ, รับแต้มย้อนหลังครั้งเดียว, รหัสเริ่มต้น 4 ตัวท้าย (เลข 0 นำหน้า), ลืมรหัส, คูปองใช้ครั้งเดียว, Tier/เมนูโปรด, และการแยกข้อมูลสมาชิก

การทดสอบกับฮาร์ดแวร์จริง (รุ่นเครื่องพิมพ์ เครื่องสแกน จอที่สอง) ต้องทำที่หน้างานด้วยปุ่มทดสอบในระบบ — ดูตาราง "อุปกรณ์ที่รองรับ" ในคู่มือ
